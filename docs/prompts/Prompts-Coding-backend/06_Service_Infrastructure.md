# PascalCalc — Backend Coding Prompts: 06 Service Infrastructure

**Phase:** 4 — Backend Implementation  
**Component:** 06 Service Infrastructure  
**Provenance:** Reconstructed prompts based on approved designs and inspected source; not evidence of original prompt execution.

## Purpose and scope

Assemble independent service routers, a legacy compatibility router, shared health checks, and HTTP lifecycle management.

## Prerequisites and dependencies

- Approved [Solution Approach](../../../Docs/SOLUTION_APPROACH.md), [System Architecture](../../../Docs/architecture.md), and [Backend HLD](../../../Docs/backend-hld.md).
- Go module `calculator-app/backend` and Project Foundation completed.
- Work in an isolated development workspace; do not modify the original project.
- Requires all prior components, especially HTTP handlers and configuration.

## Main Coding Prompt — P04-06-01

**Type:** Reconstructed main coding prompt

> Act as a senior Go backend engineer implementing PascalCalc. Follow the approved Phase 1–3 design documents and completed prerequisite components. Generate source in dependency order in an isolated workspace. Do not modify the original PascalCalc project.
> 1. Create `backend/internal/server/services.go`, `backend/internal/server/router.go`, and `backend/internal/server/run.go` in package `server`.
> 2. Implement `NewArithmeticRouter(cfg)`, `NewMathRouter(cfg)`, and `NewExpressionRouter(cfg)` as independent `*http.ServeMux` instances registering only their own API routes and `/health`.
> 3. Preserve `NewRouter(cfg)` combined legacy router for backward compatibility; register all three domains and health.
> 4. Register GET `/health` returning JSON `{ "status": "ok" }`, with a 405 for other methods.
> 5. Implement `Run(name string, defaultPort int, router func(config.Config)*http.ServeMux) error`: load optional dotenv, call `LoadForService`, build `http.Server` using host/port/timeouts, listen, and gracefully shut down on interrupt/SIGTERM using a bounded context.
> 6. Keep the server package free of Nginx/Docker configuration and avoid shared in-memory mutable evaluator instances. Return source and command results only when executed.

## Unit Testing Prompt — P04-06-02

**Type:** Reconstructed unit-testing prompt

> Act as a Go unit-test engineer. Use the code generated by the immediately preceding main coding prompt, not the original tests as a template.
> 1. Create `backend/internal/server/services_test.go` and `backend/internal/server/router_test.go` using Go `testing` and `httptest`.
> 2. Verify service-specific route isolation, combined router compatibility, health response and method rejection, and handler registration with representative requests.
> 3. Keep tests in-process; do not require external servers, Docker or Nginx. Identify any `Run` shutdown behavior that cannot be unit-tested without refactoring, and record rather than silently changing production code.
> 4. Execute `go test ./internal/server` and `go test -cover ./internal/server` if available; report measured results.

## Code Review Prompt — P04-06-03

**Type:** Reconstructed code-review prompt

> Act as a principal Go code reviewer. Use the newly generated implementation and tests and the approved design as review inputs.
> 1. Review service route isolation, backward compatibility, HTTP server timeouts, signal cleanup and graceful shutdown behavior.
> 2. Review tests for deterministic execution and route coverage. Compare generated implementation with existing server source.
> 3. Report evidence and recommended fixes; do not modify original files.
