# PascalCalc — Backend Coding Prompts: 03 Math


## Purpose and scope

Implement independent mathematical business logic: exponentiation, square root and percentage, with explicit finite-value and domain checks.

## Prerequisites and dependencies

- Approved [Solution Approach](../../../Docs/SOLUTION_APPROACH.md), [System Architecture](../../../Docs/architecture.md), and [Backend HLD](../../../Docs/backend-hld.md).
- Go module `calculator-app/backend` and Project Foundation completed.
- Work in an isolated development workspace; do not modify the original project.
- Arithmetic component is not a runtime dependency; Math uses only Go standard library and the foundation.

## Main Coding Prompt — P04-03-01

**Type:** Reconstructed main coding prompt

> Act as a senior Go backend engineer implementing PascalCalc. Follow the approved Phase 1–3 design documents and completed prerequisite components. Generate source in dependency order in an isolated workspace. Do not modify the original PascalCalc project.
> 1. Create `backend/internal/mathops/service.go` in package `mathops`.
> 2. Define stateless `Service` and `NewService() *Service`.
> 3. Implement `Power(a,b float64) (float64,error)`, `SquareRoot(a float64) (float64,error)`, and `Percentage(a,b float64) (float64,error)`; percentage means `(a/100)*b`.
> 4. Reject NaN and infinities for inputs; reject non-finite Power and Percentage results. For negative square root return `cannot calculate square root of a negative number`; use `math.Pow` and `math.Sqrt`.
> 5. Preserve the existing error behavior: `inputs must be finite numbers`, `input must be a finite number`, `invalid exponentiation result`, `invalid percentage result` as appropriate.
> 6. Provide `isFinite(float64) bool` helper; avoid HTTP, JSON, other services, or arbitrary rounding.
> 7. Output complete source and commands; report execution only if run.

## Unit Testing Prompt — P04-03-02

**Type:** Reconstructed unit-testing prompt

> Act as a Go unit-test engineer. Use the code generated by the immediately preceding main coding prompt, not the original tests as a template.
> 1. Create `backend/internal/mathops/service_test.go` using `testing`, preferably table-driven.
> 2. Cover Power normal, zero, negative exponents, invalid fractional powers of negative bases, and overflow; SquareRoot positive/zero/negative/nonfinite; Percentage ordinary, zero, negative, nonfinite and overflow.
> 3. Assert results and exact error behavior; use tolerance only where mathematically justified.
> 4. Run `go test ./internal/mathops` and `go test -cover ./internal/mathops` if possible; capture actual results. No HTTP tests or modifications to production code.

## Code Review Prompt — P04-03-03

**Type:** Reconstructed code-review prompt

> Act as a principal Go code reviewer. Use the newly generated implementation and tests and the approved design as review inputs.
> 1. Review `service.go` and `service_test.go` for signatures, finite-value handling, error wording, domain correctness and coverage.
> 2. Compare generated behavior against the existing Math service; classify Pass/Partial/Fail/Not verified and record command evidence.
> 3. Recommend corrections without modifying the original code.
